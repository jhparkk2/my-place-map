# 나와봄 계정 삭제 — 배포 전 검증 계획

**상태: 코드 초안만 작성됨.** Edge Function 소스: `supabase/functions/delete-my-account/index.ts`. **Supabase에 배포하거나 앱에서 호출하도록 연결하지 않았습니다.** 실제 계정 13개 장소·공유 자료를 삭제하지 마세요.

## 설계한 처리 경로

1. 사용자가 이메일로 로그인하고 삭제 확인 문구 `나와봄 계정 삭제`를 입력합니다.
2. Edge Function은 요청에 담긴 **Bearer JWT**를 Supabase에서 검증하여 소유 계정 ID를 확보합니다. 브라우저가 전송한 임의 사용자 ID는 받지 않습니다.
3. 관리자 역할은 오직 Edge Function 환경 변수에만 사용합니다. 프론트엔드에 service_role 키를 넣지 않습니다.
4. 해당 사용자 UID의 비공개 백업/동기화 Storage 파일과 **현재 이메일 계정 UID로 만든 공개 공유 파일**을 정리합니다.
5. 현재 이메일 UID의 반응 집계 데이터를 정리한 뒤 Supabase 인증 계정 삭제를 시도합니다.
6. 브라우저의 IndexedDB·자동 복원본·사용자 JSON 내보내기 파일 및 **과거 익명 UID로 만든 공유 파일은 자동 삭제 대상이 아닙니다.** 이 상태로는 완전 삭제라고 표시할 수 없습니다.

## 정식 배포 전 차단 조건

- [ ] 실제 Supabase 프로젝트를 별도 테스트 계정으로 복제·격리
- [ ] 인증된 사용자 외 요청 차단 및 이메일 로그인에서만 삭제 허용되는지 확인
- [ ] Storage 파일 목록의 계정 별 분리와 100개 이상 페이지네이션 검증
- [ ] 일부 Storage 삭제 실패 시 인증 계정 삭제가 수행되지 않는지 확인
- [ ] 반응 집계 삭제 권한과 참조 무결성 확인
- [ ] 사용자가 과거 익명 로그인으로 만든 공유 파일까지 추적·삭제 가능한 설계 완성
- [ ] 이메일 계정 탈퇴 후 해당 기기의 동기화 자동 활성화 및 데이터 재업로드 방지
- [ ] 브라우저 로컬 데이터 삭제 여부를 사용자가 **명시적으로 선택**하도록 UI 구성, 안전한 백업·오작동 복구 시나리오 검증
- [ ] 계정 삭제 완료·실패·일부 완료 메시지를 사용자가 이해할 수 있도록 설계
- [ ] 운영자 개인정보 문의 창구, 실제 처리방침, 보유기간 검토 완료

## 추가 운영 주의

현재 자동 동기화는 최근 수정 시간 기준의 단순 병합 방식입니다. 서로 다른 기기의 수정·삭제 충돌, 오프라인 모드, 복원본 보존, 과거 수동 백업과의 관계를 정식 공개 전 추가로 시험해야 합니다.

**검증 전에는** 사용자에게 계정 삭제 실행 버튼을 노출하지 않습니다. 관리 화면에는 안전한 설명과 JSON 내보내기만 제공합니다.
