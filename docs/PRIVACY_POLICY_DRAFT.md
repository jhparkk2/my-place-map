# 나와봄 개인정보처리방침 (운영 전 검토용 초안)

> **아직 확정되지 않은 초안입니다.** 이 문서는 곧바로 정식 이용자에게 적용할 처리방침이 아닙니다. 운영자 신원·연락처·시행일·Supabase 저장 지역·개인정보 위탁/국외 이전 사실관계·실제 보유기간을 확인하고 최종 문구를 확정해야 합니다.

- 서비스: **나와봄** — 실제 방문 장소를 지도·사진·후기로 기록하는 웹앱
- 개인정보처리자: **[운영자 성명 또는 상호 입력 필요]**
- 개인정보 문의: **[실제 수신 가능한 문의 이메일 입력 필요]**
- 시행일: **[확정 필요]**
- 버전: 출시 준비 초안 (2026-11-14)

## 1. 처리 목적과 항목

| 구분 | 처리할 수 있는 항목 | 목적 | 선택 여부 |
| --- | --- | --- | --- |
| 이메일 로그인 | 이메일 주소, Supabase 사용자 ID 및 인증 세션 | 본인 인증, 서버 백업/기기 간 동기화 | 선택 |
| 개인 장소 기록 | 장소명, 주소·좌표, 방문일, 사진, 후기, 별점, 재방문·좋아요, 댓글 | 방문 장소 기록·검색·지도/앨범 보기 | 사용자가 입력 |
| 공유 링크 | 선택한 장소 정보, 사진 및 공유 ID | 이용자가 지정한 공개 링크 생성·표시 | 사용자가 별도 실행 |
| 장소 반응 | 장소 식별 키, 익명 또는 일반 로그인 사용자 ID, 조회·좋아요 여부 | 중복 반응 처리 및 공용 집계 | 기능 이용 시 |
| 접속·기술 정보 | 호스팅/지도/인증 제공업체가 접속 과정에서 처리할 수 있는 정보 | 서비스 제공·보안 | **실제 공급자 처리 현황 확인 필요** |

서비스는 장소 기록에 실제 사람의 얼굴·주소·연락처 같은 개인정보가 포함될 수 있으므로 사용자가 공유 범위를 확인한 다음 기록·공유하도록 안내합니다. 정확한 위치정보의 처리 및 관련 별도 법적 의무는 정식 공개 전 점검합니다.

## 2. 어디에 저장되나요?

1. **기기 저장**: 기본 장소 기록과 사진은 이 기기 Safari 등 브라우저의 IndexedDB에 저장됩니다. 복원·동기화 설정 등 추가 정보는 다른 브라우저 저장 공간에 남을 수 있습니다. **로그아웃만으로는 기기 기록이 삭제되지 않습니다.**
2. **서버 백업·동기화(선택)**: 이메일로 로그인한 이용자가 직접 서버 백업 또는 자동 동기화를 켜면 장소·후기·사진이 Supabase 비공개 Storage에 계정별로 저장됩니다. 기기 간 동기화는 앱이 열려 있고 인터넷이 연결된 때에 동작하며 완전한 실시간·백그라운드 동기화는 보장하지 않습니다.
3. **공개 공유**: 이용자가 사진 포함 공유 링크를 직접 준비하면 선택한 사진 한 장과 장소 요약을 별도의 공개 Storage에 업로드합니다. **링크를 알고 있는 사람은 정보를 열람·재전달할 수 있습니다.** 공개 링크를 취소·일괄 삭제하는 기능은 아직 구현되지 않았습니다.

## 3. 외부 서비스, 위탁 및 국외 이전

현재 소스에 GitHub Pages(호스팅), Supabase(이메일 인증·Storage·반응 집계), Kakao(검색·공유), OpenStreetMap(지도 타일)이 사용됩니다. 다만 각 서비스에서 실제 처리하는 정보, 역할(수탁·제3자 제공 등), 보관 장소, 국외 이전의 근거 및 고지사항을 **운영자가 계약·설정·공급자 문서로 확인해야 합니다.** 확인되지 않은 사항을 임의로 기입해서는 안 됩니다.

## 4. 보유 및 삭제

- **기기 기록**: 이용자가 앱에서 개별 장소를 삭제하면 현재 브라우저의 해당 장소가 삭제됩니다. 이전에 저장한 JSON 파일, 기기 내 복원본, 기존 수동 서버 백업 파일 등에는 별도 기록이 남을 수 있습니다.
- **비공개 서버 기록**: 개별 장소의 동기화 삭제가 반영되더라도 기존 수동 백업 파일에 같은 정보가 남을 수 있습니다. 모든 보관본의 삭제는 별도 절차가 필요합니다.
- **이메일 계정 탈퇴**: 서버 측 인증 계정과 해당 사용자 ID 소유 파일을 정리하는 기능의 *코드 초안*만 준비되어 있습니다. **현재 실제 서비스에 계정 완전 삭제 기능이 배포·검증되었다고 안내해서는 안 됩니다.**
- **기존 익명 계정 공유 파일**: 이메일 사용자 ID와 연결되지 않은 과거 익명 계정으로 공유한 파일은 일반 이메일 계정 탈퇴에 자동으로 포함되지 않을 수 있습니다.
- **법적 보존**: 법령상 별도 보존이 필요한 데이터 유무·기간 및 파기 방식을 운영자가 확정해야 합니다.

## 5. 이용자의 권리 및 문의

이용자는 자신의 기록을 확인·수정·내보내기할 수 있습니다. 열람·정정·삭제·처리정지, 로그인·동기화와 관련한 문의를 접수할 운영자 창구는 **[실제 문의 이메일 확정 후 공개]**로 준비해야 합니다. 현재 서비스에서 직접 지원하지 않는 요청에는 별도 처리 절차를 수립해야 합니다.

## 6. 안전성 보호조치

비공개 서버 Storage는 로그인한 계정의 폴더만 접근하도록 RLS 정책을 적용하도록 설계되었습니다. 서버 관리자 권한은 브라우저 코드에 저장하지 않습니다. 계정 변경 시 다른 계정으로 실수 전송되는 위험을 줄이기 위한 기기 보호 검사도 있습니다. 다만 브라우저 기록은 이메일 로그아웃으로 잠기거나 암호화되지 않으므로 공용 기기를 사용하지 않도록 권장합니다. 모든 보안 통제가 실환경에서 검증된 것은 아닙니다.

## 7. 자동 수집, 쿠키 및 민감정보

브라우저 저장 정보·로그인 세션 등의 동작을 실제 배포 환경에서 확인해야 합니다. 별도 광고·분석 SDK를 추가한다면 처리 항목·제3자/위탁·쿠키 정책을 다시 검토해야 합니다. 민감정보나 타인의 동의 없는 개인정보를 사진/후기에 올리지 않도록 안내 문구를 마련해야 합니다.

## 8. 변경 및 공지

이 방침은 **확정 이후** 실제 시행일과 개정 이력을 기재하고 이용자가 언제든 볼 수 있도록 사이트에 공개해야 합니다.
